# lean-work

> Тот же (или лучший) результат в Claude Code при меньшем расходе лимитов.

[English version](README.md)

**Статус: v0.1 (экспериментальный).** Правила основаны на том, как Claude Code тратит токены, но экономия **ещё не измерена**. Протокол A/B-проверки лежит в [`evals/tasks.md`](evals/tasks.md). Цифры появятся здесь после замеров; до тех пор считайте это гипотезой, которую можно попробовать.

## Проблема

Каждое сообщение в сессии Claude Code заново отправляет всю историю. Лимиты сгорают в основном из-за раздутого контекста, а не из-за полезной работы:

- чтение файла целиком, когда нужны были несколько строк
- 500 строк пройденных тестов ради одной ошибки
- массовое чтение и правки на самой дорогой модели
- одна бесконечная сессия со старым контекстом от прошлых задач
- неверно понятая задача и переделка

## Идея

Резать мусор, но не информацию, нужную для решения. `lean-work` добавляет один скилл `efficient-work`, который Claude подгружает в начале нетривиальных задач.

### 1. Триаж (шаг 0)

Три быстрые проверки перед работой:

| Проверка | Решение |
|---|---|
| **Ясность**: есть ли развилка, где ошибка дорого стоит? | Задать 1-3 вопроса с вариантами и рекомендацией. Иначе прочитать код, а не спрашивать. |
| **Размер** | Маленькая: делать сразу. Большая: сначала короткий план. |
| **Риск**: архитектура, удаление, прод, безопасность? | Решает сильнейшая модель. Рутину можно делегировать. |

Тривиальные задачи (опечатка, переименование, одна строка) пропускают триаж, поэтому там скилл не добавляет расхода.

### 2. Маршрутизация по моделям

| Подзадача | Модель |
|---|---|
| Понимание, план, архитектура, финальная проверка | сильнейшая модель |
| Широкий поиск, чтение многих файлов, запуск тестов, массовые правки по чёткому плану | саб-агент `sonnet` |
| Форматирование, переименования, простые справки | саб-агент `haiku` |

Исполнители не принимают архитектурных решений, а итог всегда проверяет сильнейшая модель.

### 3. Чистый контекст (только безопасные правила)

- Сначала Grep/Glob, потом чтение нужного диапазона.
- Не перечитывать то, что уже в контексте.
- Шумный вывод: показывать ошибки и итоговую строку, указывать, где полный вывод.
- Широкие поиски отдавать саб-агенту, возвращаются только выводы.
- План перед правкой 3+ файлов; тесты после изменений кода.
- Предлагать `/clear` при смене темы и `/compact` на длинных задачах.

### Защита качества

Скилл прямо запрещает оптимизации, которые рискуют качеством: отказ читать файл целиком, дешёвые модели для неясных или рискованных решений, сжатие контекста с потерей нужных деталей, сокрытие ошибок ради экономии.

## Установка

```
/plugin marketplace add resccrew/lean-work
/plugin install lean-work@lean-work
/reload-plugins
```

Попробовать без установки: `claude --plugin-dir <путь к клону>`.

## Как правило попадает в плагин

Каждое правило проходит два барьера на задачах из [`evals/tasks.md`](evals/tasks.md):

1. **Качество**: результат не хуже (тесты зелёные, критерии выполнены).
2. **Экономия**: токенов меньше, чем в базовом прогоне.

Правила, не прошедшие хотя бы один барьер, удаляются. Правила, которые улучшают качество без экономии (например, «сначала план»), остаются.
